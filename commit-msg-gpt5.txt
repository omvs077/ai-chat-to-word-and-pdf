Fix ChatGPT code blocks (real div/cm-line structure) and lost bold-styled links

Both bugs found by generating and inspecting a fresh real ChatGPT export
after the previous round's fix - confirmed that fix's "success" was a
false read (see below), and separately root-caused one of the two
findings explicitly deferred last round.

1. Code blocks still corrupted, differently than before. The previous
   round's normalizeCodeBlocks() only handled <pre class="cm-content">
   with per-token <span> children - a real structure confirmed via live
   DevTools earlier in this session. A fresh live inspection this round
   showed the ACTUAL current live structure is different:
   <div class="cm-content" data-language="python"><div class="cm-line">
   ...</div>...</div> - one div per source line, no <pre> tag at all. The
   previous fix's querySelectorAll('pre') matched nothing on this real
   structure, so it silently did nothing - the export still showed
   escaped, line-by-line corrupted code. (The disappearance of backslash-
   escaping noted at the time was coincidental, not the fix working - a
   side effect of different surrounding text context changing which
   characters Turndown's escape heuristic happened to flag.)

   Fix: normalizeCodeBlocks() now handles both real structures - the div/
   cm-line shape (reading data-language directly off the element, joining
   each .cm-line's textContent with real \n characters) and the pre/span
   shape from before, kept as a fallback since it's an equally real,
   independently-confirmed structure, not speculative. Verified end-to-end
   through the real vendored Turndown library: produces a genuine
   ```python fenced block with correct indentation and blank lines
   preserved, not escaped plain paragraphs.

   Also fixed a bug in the fix itself, caught by writing tests for both
   shapes separately rather than assuming they're independent: both real
   structures share the literal class "cm-content" (confirmed - the <pre>
   variant is class="cm-content q9tKkq_readonly m-0"), so the div-shape
   handler was matching the pre-shape element too, finding zero .cm-line
   children, and replacing it with an empty <pre><code></code></pre>
   before the pre-shape fallback ever got a chance to run. Now guarded on
   actually having .cm-line children before treating something as the
   div shape.

   Still NOT handled: a "Python" language-label header and "Run" button
   that sit as siblings near the code block still leak into captured text.
   Their real wrapper markup hasn't been confirmed via live inspection -
   deliberately not guessed at.

2. Three real links (Python Documentation / MDN Web Docs / freeCodeCamp)
   were completely lost - not just unstyled, absent entirely. Root cause,
   confirmed independent of anything ChatGPT-specific (lib/markdown-
   blocks.js is shared by both adapters and both generators):
   parseInlineRuns's bold/italic regex captures inner content as a raw
   string without re-parsing it for nested markdown. ChatGPT renders these
   particular cited-source links as an entire **bold** span wrapping
   nothing but a link ("**[text](url)**") - Turndown itself converts this
   correctly, and the real <a href> is correctly extracted upstream, but
   parseInlineRuns then read the bold span's inner "[text](url)" as
   literal bracket/paren text instead of a link, silently dropping the URL
   while still rendering the visible bold text - which is exactly why it
   looked merely "unstyled" rather than obviously broken.

   Fix: when an entire bold/italic span's content matches a link pattern
   (the specific, confirmed real case - not general recursive inline
   parsing, which this file's own header explicitly scopes out), the
   resulting run now carries both the bold/italic flag and the link.
   Verified end-to-end through both real generators: a real
   ExternalHyperlink relationship in the actual generated .docx, and a
   real /Subtype /Link annotation with a real /URI in the actual generated
   .pdf - not just an intermediate parse-result check.

Test suite: 43 -> 46 passing tests.
