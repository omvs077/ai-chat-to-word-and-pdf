Fix interrupted-response export race, banner glyph leak, and DOCX image format mislabeling

Root-caused via a real conversation export (search-generated images + a
deliberately interrupted long response) that surfaced three separate,
previously-unknown bugs:

1. Streaming-race truncation (content.js): exporting right as/after
   clicking Stop could capture a stale DOM snapshot from mid-generation,
   silently dropping real generated text and losing the interrupted-state
   notice entirely. Confirmed via direct execution that content.js's scrape
   and Turndown's conversion were both already correct - the DOM read
   itself was just too early. Each assistant turn's wrapper carries a real
   data-is-streaming="true"/"false" attribute; extraction now polls on it
   (up to 15s) before reading anything.

2. Interrupted-response banner (content.js): the "Claude's response was
   interrupted." notice renders its icon via a private-use-area icon-font
   codepoint (\ue08f) with no glyph in the embedded PDF/DOCX fonts - almost
   certainly the real root cause of a historical mojibake-glyph bug from an
   earlier session. Its Edit prompt/Try again buttons also leaked into
   markdown as literal trailing text. Both replaced with a clean
   "[Response was interrupted]" marker instead of leaking raw content or
   silently dropping the notice.

3. DOCX image format mislabeling (lib/docx-generator.js +
   lib/vendor/docx.umd.js): the vendored ImageRun hard-codes every embedded
   image's filename as <id>.png regardless of real format. Confirmed via a
   real exported .docx: 6 of 7 embedded images (2 WEBP, 3 JPEG, 1 AVIF) were
   mislabeled, declaring non-PNG bytes as image/png in [Content_Types].xml -
   which breaks rendering in Word, not just cosmetics. JPEG now gets its
   correct .jpg extension (content-type already existed, rename-only fix).
   WEBP gets a corrected .webp extension plus a one-line addition to the
   vendored ContentTypes class (Word also refuses parts with no declared
   content-type at all). AVIF has no realistic Word support regardless of
   correct labeling, so it now falls back to the same text placeholder
   already used for undecodable images, instead of embedding bytes Word
   can't open either way.

Also fixed: 5 instances of pre-existing UTF-8 corruption in
tests/content.test.js (a stray raw 0xB7 byte where a proper UTF-8 middle-dot
should be, in "Document · MD" artifact-card fixture text) - present since
an earlier session's commit, unrelated to this session's changes, found
while UTF-8-validating the files this session touched.

tests/helpers/dom-harness.js: added an optional onReady(window) hook to
runExtraction() so tests can schedule delayed DOM mutations (used by the
new streaming-wait test to prove it actually blocks and picks up
settled content, not just that it doesn't throw).

Test suite: 25 -> 30 passing tests. Two new tests use real DOM markup
captured via live DevTools inspection of an actual interrupted response
(not simplified stand-ins); three new tests use small but genuinely valid
WEBP/JPEG fixtures with real magic bytes.
